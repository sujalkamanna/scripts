# Installing and Setting Up Docker Swarm

## 1. Install Docker Engine

📍 Run on: ALL nodes (Manager + Worker nodes)

Install Docker Engine using the official Docker repository.

bash

```bash
#!/bin/bash

set -e

echo "🔧 Updating system packages..."

sudo apt update

echo "📦 Installing prerequisites..."

sudo apt install -y ca-certificates curl

echo "🐳 Installing Docker Engine..."

curl -fsSL https://get.docker.com | sudo sh

echo "🚀 Enabling Docker service..."

sudo systemctl enable docker
sudo systemctl start docker

echo "🔍 Verifying Docker installation..."

docker --version
docker compose version

sudo systemctl status docker --no-pager

echo "✅ Docker installation completed!"
```

Note: Run this script on every Manager and Worker node.

## 2. Initialize Docker Swarm

📍 Run on: MANAGER node only

Initialize the Swarm cluster using the Manager's private IP address.

bash

```bash
docker swarm init --advertise-addr <MANAGER_PRIVATE_IP>
```

Example:

bash

```bash
docker swarm init --advertise-addr 10.0.1.10
```

Expected output:

text

```text
Swarm initialized: current node (xxxxxxxx) is now a manager.

To add a worker to this swarm, run the following command:

docker swarm join --token SWMTKN-1-xxxxxxxx \
10.0.1.10:2377
```

Save the worker join token securely.

## 3. Get Worker Join Token

📍 Run on: MANAGER node only

To retrieve the worker join command:

bash

```bash
docker swarm join-token worker
```

To retrieve the manager join command:

bash

```bash
docker swarm join-token manager
```

To rotate the worker join token:

bash

```bash
docker swarm join-token --rotate worker
```

Security Treat join tokens as credentials. Do not publish them in scripts, Git repositories, or logs.

## 4. Join Worker Nodes

📍 Run on: WORKER nodes only

Execute the worker join command generated by the Manager.

bash

```bash
docker swarm join \
  --token <WORKER_JOIN_TOKEN> \
  <MANAGER_PRIVATE_IP>:2377
```

Example:

bash

```bash
docker swarm join \
  --token SWMTKN-1-xxxxxxxx \
  10.0.1.10:2377
```

Expected output:

text

```text
This node joined a swarm as a worker.
```

Repeat this process on all Worker nodes.

## 5. Verify Docker Swarm Cluster

📍 Run on: MANAGER node only

Check all nodes:

bash

```bash
docker node ls
```

Example output:

text

```text

def456        worker-01   Ready     Active
ghi789        worker-02   Ready     Active
```

Check detailed node information:

bash

```bash
docker node inspect self
```

Check Swarm status:

bash

```bash
docker info | grep -A 10 Swarm
```

## 6. Configure Firewall and Security Groups

📍 Apply on: ALL nodes

Allow the following ports for communication between Swarm nodes.

| Port | Protocol | Purpose |
| --- | --- | --- |
| 2377 | TCP | Cluster management |
| 7946 | TCP/UDP | Node communication |
| 4789 | UDP | Overlay network traffic |

Important Restrict these ports to the private IP addresses or private subnet of your Swarm nodes. Do not expose them publicly.

Example using UFW:

bash

```bash
# Swarm management
sudo ufw allow from <PRIVATE_SUBNET> to any port 2377 proto tcp

# Node communication
sudo ufw allow from <PRIVATE_SUBNET> to any port 7946 proto tcp
sudo ufw allow from <PRIVATE_SUBNET> to any port 7946 proto udp

# Overlay network
sudo ufw allow from <PRIVATE_SUBNET> to any port 4789 proto udp

# Check firewall rules
sudo ufw status
```

Replace `<PRIVATE_SUBNET>` with your actual private subnet, such as `10.0.1.0/24`.

## 7. Deploy a Test Docker Swarm Service

📍 Run on: MANAGER node only

Deploy an Nginx service with two replicas.

bash

```bash
docker service create \
  --name web \
  --publish published=80,target=80,protocol=tcp,mode=ingress \
  --replicas 2 \
  nginx:alpine
```

Check the service:

bash

```bash
docker service ls
```

Check individual containers:

bash

```bash
docker service ps web
```

Check service logs:

bash

```bash
docker service logs web
```

## 8. Access the Deployed Service

📍 From: Any browser or client machine

Access the service using any Swarm node's IP address:

text

```text
http://<MANAGER_PRIVATE_IP>
```

Or:

text

```text
http://<WORKER_PRIVATE_IP>
```

Docker Swarm's routing mesh routes incoming traffic to an available service replica, even if that replica runs on another node.

## 9. Useful Docker Swarm Commands

| Operation | Command |
| --- | --- |
| Check cluster nodes | `docker node ls` |
| List services | `docker service ls` |
| Inspect service | `docker service inspect web` |
| Scale service | `docker service scale web=4` |
| View service logs | `docker service logs -f web` |
| Remove service | `docker service rm web` |
| Leave Swarm | `docker swarm leave` |
| Remove worker node | `docker node rm <NODE_ID>` |
| Drain a node | `docker node update --availability drain <NODE_ID>` |
| Activate a node | `docker node update --availability active <NODE_ID>` |

## Important Production Recommendations

- Use at least 3 Manager nodes for production high availability (or 5 for larger clusters).
- Use private IP addresses for Swarm communication.
- Configure TLS and secure SSH access for administration.
- Back up `/var/lib/docker/swarm` on Manager nodes securely.
- Use Docker secrets for passwords, API keys, and certificates.
- Avoid running application workloads on Managers in production by configuring node availability appropriately.
- Keep Docker Engine versions consistent across nodes.
